# 农业饲料法规知识库实施计划

> For Hermes: 按 subagent-driven-development 节奏推进;每阶段结束跑质量门(构建+OCR+索引一致性 + 前端 LCP)再进入下一阶段。

**Goal:** 基于《中国农业饲料法规 2026 版》搭建可在线访问、按章节切分的 RAG 知识库,Web App 形态,支持扫描版 OCR 增量更新。

**Architecture:** 两段式
- **构建段**(本地/自托管):法规 PDF → MinerU OCR → 章节级 Markdown → GraphRAG 抽取实体/关系 → 导出索引
- **查询段**(Cloudflare 边缘):Workers + Vectorize + D1 + R2 跑检索/重排;Pages 托管响应式前端

**Tech Stack:**
- 数据/构建: MinerU(opendatalab/MinerU) · GraphRAG(microsoft/graphrag) · bge-large-zh-v1.5(本地 Embedding) · DeepSeek-V3(云端 LLM)
- 查询/前端: Cloudflare Pages + Workers + Vectorize + D1(SQLite) + R2 对象存储
- 前端: Vite + React 18 + Tailwind + shadcn/ui + react-markdown

---

## 数据切分原则(关键)

| 类型 | 拆分方式 | 为什么 |
|---|---|---|
| 文本型法规(本期) | Markdown 按 `## 第X章`、`### 第X条` 拆 chunk | 法规天然有目录/条文,按章节保证每段独立语义 |
| 扫描型法规(后续) | MinerU 输出 Markdown(含 OCR 文本 + 版面坐标),再按目录切 | 扫描版无原文,必须先 OCR;章节标题靠版面坐标识别 |
| 章节级 chunk 元数据 | `{ doc_id, chapter, article, title, entities[], page_ref }` | 召回时直接定位条文,前端高亮原文出处 |

**绝不**使用 LangChain `RecursiveCharacterTextSplitter` 这类按字符切分的方案。

## 阶段 D·索引导出 + 上传

**Files:**
- `build/export/flatten.py` — 把 GraphRAG 产物扁平化为 JSON
- `build/export/push_to_r2.sh` — 用 wrangler 上传 R2 + 写入 D1 metadata

**导出 schema:**
- `entities.json`: `{id, name, type, description, chapter_refs[]}`
- `chunks.json`: `{chunk_id, doc_id, chapter, article, text, entities[], page_ref}`
- `community_summaries.json`: `{community_id, level, summary, entities[]}`
- `vector_meta.json`: 准备往 Vectorize 灌的 `{id, values, metadata}` 分批(.bin 文件)

**Step 1**: flatten 脚本 → 4 个 JSON
**Step 2**: bge-large-zh 对 chunks 生成 embedding(本地)
**Step 3**: 写 D1 schema:`documents / chapters / chunks / entities` 4 张表
**Step 4**: 上传 R2 + 写入 D1;embedding 灌 Vectorize(`wrangler vectorize insert`)

## 风险与对策

| 风险 | 对策 |
|---|---|
| GraphRAG 中文 prompt 效果差 | 覆盖默认 prompt,先小样本回归再全量 |
| MinerU 对低质扫描件识别率低 | 加人工校对 UI,标记低置信度段落 |
| Cloudflare Vectorize 单向量 1536 dim 上限 | bge-large-zh 1024 dim 兼容;后续可换 bge-m3 |
| 法规版本更新频繁 | 提供 `graphrag update --incremental` 流程 |

## 四、🟡 三个警告

### 4.1 HTML 实体未反转义（1572 处 / 16 条条文）

OCR 把 `<` 转义成 `&lt;` 后**没有反转义**就写进了正文：

```
原文应是:  1 ）一级母离子 m/z<200 时，其绝对偏差应<1 mDa
库里是:    1 ）一级母离子 m/z&lt;200 时，其绝对偏差应&lt;1 mDa

原文应是:  辅酶Q10渣<sup>4e</sup>
库里是:    辅酶Q10渣&lt;sup&gt;4e&lt;/sup&gt;
```

| 实体 | 出现次数 |
|---|---|
| `&lt;` | 1522 |
| `&gt;` | 50 |

**影响**：
1. 用户看到的正文带原始标记，不是「<」
2. **带符号的查询匹配不上** —— 搜 `m/z<200` 命中不了正文里的 `m/z&lt;200`
3. 上标标签彻底不可读（`<sup>4e</sup>` 本意是「4e」的上标）

**涉及文档**：《饲料原料目录》《饲料添加剂品种目录》《饲料中风险物质的筛查与确认导则》等。

**修复成本**：低 —— 一次批量反转义（`html.unescape`），但要**同步重灌 FTS**
（FTS 的 text 是正文派生的，不重灌会留下两套不一致的正文）。

### 4.2 物质目录缺英文名（313 / 387 条 = 81%）

```
no_en: 313 / 387     no_src: 0 / 387
```

《饲料添加剂品种目录》**本身是双语的**，缺 `name_en` 是抽取环节的缺口，不是源数据没有。

**实测影响**（生产实体接口）：

| 查询 | 结果 |
|---|---|
| `/api/entity/烟酰胺` | ✅ 命中，2 条关联条文 |
| `/api/entity/Nicotinamide` | ❌ **entity_not_found** |

即**英文名检索不到实体**。双语检索目前只对那 74 条有英文名的物质有效。

### 4.3 正文完全重复（15 条 / 6 组）

同一文档内，正文**逐字节相同**的条文：

| 重复数 | 文档 | 长度 | 内容 |
|---|---|---|---|
| ×3 | 饲料添加剂安全使用规范 | 2986 字 | `0.6 ～0.7 mg/kg` 表格段 |
| ×3 | 「瘦肉精」专项整治通知 | 2996 字 | 养殖场表格 |
| ×3 | 转基因生物安全评价指南 | 2976 字 | 改良试验数据 |
| ×2 | 宠物饲料管理公告 | 55 字 | （五）主要机构负责人证书 |
| ×2 | 宠物饲料管理公告 | 46 字 | （四）企业组织机构图 |

**成因**：扫描件同一表格跨页被重复 OCR / 切分时被切成了多条。
长正文（~3000 字，正好是切分上限）重复 3 次 = **同一表格的 3 个分片内容雷同**。

**影响**：检索会返回多条一模一样的命中，挤占 top-k 名额，降低结果多样性。
**不算错误**（内容本身是对的），但属于可以清理的冗余。

### 两个「看起来像问题但其实不是」的

**① 33 个孤儿实体** —— 分布 `ACTION 7 / SUBSTANCE 5 / 空 5 / PARTY 4 / CERTIFICATE 3 / PENALTY 2 / LAW 2 / DOCUMENT 2 / 其他 4`。
ADR-004 明确决策：「④ 图谱保持空壳直到有真实用例」，实体↔实体关系**刻意不排期**。
其中 5 个标成 `SUBSTANCE` 的是 GraphRAG 抽取的概念（「产品」「产品质量」）**类型标错**，但不影响检索。

**② 章节内 `sort_order` 有跳号** —— `sort_order` 是**全局**编号（跨章节递增），
同一文档多个章节共享编号空间，单章节内天然有跳号。
实测「十四五」规划文档 3 个章节都有跳号，但 `ORDER BY sort_order` 渲染出来**顺序完全正确**。
判据应该是「排序后不重复」而不是「连续无跳号」—— 后者会把这个正常现象误报成缺陷。

## 八、复现方式

```bash
# 全量体检(只读)
python build/export/quality_report.py --check

# 带 JSON 输出
python build/export/quality_report.py --check --json quality.json
```

**体检脚本的 25 项检查**分四类：
- **结构**:外键、层级、排序、标题、FTS 覆盖、FTS 与 articles 一致性
- **纯净**:旧语料残留、乱码、HTML 实体、重复正文、article_id 复用
- **业务**:合规闸门、规则溯源、物质目录完整性、别名歧义、图谱孤儿
- **链路**:bge 语料对齐、生产检索实调（含降级检测）

> ⚠️ 脚本对 D1 读超时与生产接口超时都做了重试 ——
> **网络抖动报成「数据坏了」是最容易误导人的错误**（本次就遇到 2 次）。

## 九、诚实标注：这次体检**查不出来**的东西

| 盲区 | 为什么查不出 | 怎么补 |
|---|---|---|
| **原文准确性** | 只能判断结构/字符/编码,**判断不了「这段话是否忠于原文」** | GB10648 那 6 处错误是**逐页目视比对 PDF** 才发现的 —— 自动化查不出语义错误 |
| **切分粒度是否合理** | 「一条 = 一个语义单元」无法用规则判 | 需人工抽样审阅，或用 LLM 评判 |
| **检索结果的相关性** | 只测了「有没有命中」,没测「排得对不对」 | 需更完整的标注集（当前 50 条 eval 用例） |
| **LLM 回答的忠实度** | 引用准确率 eval 用的是**基线缓存离线复算**，没打真实 API | 需 `eval_qa_faithfulness.py` 接真实接口跑全量 |
| **表格语义** | 241 条含表格的条文,表格里的行列关系**没有结构化验证** | 需逐表核对（本项目已有 `scanned-table-ocr-md` 流程） |
| **时效性** | 语料是 2026 版汇编，**不知道哪些条款已被新公告修订** | 靠 ⑤ 监测（已上线），但改动入库路径 `ingestRelease` 还没开 |

2《面向饲料法规的智能体》文档分析

E:\workspace\siliao\面向饲料法规的智能体.docx
早期需求构想稿（63 行）—— 不是落地方案

核心是一个 5 步 Agent 流程，以「这种预混料在猪饲料中的添加量合规吗？」为示例问题。

Step1 意图识别→ Step2 任务拆解→ Step3 工具调用→ Step4 结果融合→ Step5 输出生成

Step1 提取实体（产品类型 / 动物种类 / 属性），Step3 分派三类工具：向量检索、知识图谱、规则引擎。

四大功能模块

模块子能力
① 法规检索 语义检索（自然语言查询）· 层级导航（条例→办法→公告→条款）· 版本追溯（修订记录与现行有效版本）
② 合规审查 配方审查（比对禁用清单和限量标准）· 标签审查（GB 10648）· 企业资质审查（生产许可证、批准文号有效性）
③ 风险预警 法规变更预警（监测农业农村部新公告）· 抽检结果预警 · 合规日历（换证/年检/过渡期）
④ 知识问答 多轮对话追问 · 引用自动标注到具体条款（如《条例》第十四条第二款）· 复杂问题拆解后分步回答

架构主张

RAG + 知识图谱 + 规则引擎 三者互补 「RAG 解决语义理解、知识图谱解决关系推理、规则引擎解决精确计算，三者互补， 能够覆盖饲料法规场景中从『模糊查询』到『精确合规判定』的完整需求链。」

对照现实：这三件里，RAG 已落地，知识图谱是空表，规则引擎是零代码。

数据更新机制（文档自述的关键难点）

农业农村部官网 / 国家饲料质量检验中心
        │
        ▼  公告监测爬虫（每日定时）
        │
        ▼  变更检测 → 增量更新向量库 + 图谱 + 规则引擎
        │
        ▼
  影响分析 → 向订阅用户推送预警

完全未实现

仓库内无爬虫代码、无定时任务、无订阅推送逻辑。

6关键差距判断

核心结论 方案里的 「规则引擎 + 知识图谱 + 变更监控」三大件，代码里一个都没有。 当前系统是纯 RAG 检索问答系统，能力边界卡在「找到条款并原文引用」。

这意味着什么

  • 构想稿的「预混料添加量是否合规」→ 当前答不了。系统只能告诉你「哪些条款规定了添加量」，无法给出「合规 / 不合规」判定。
  • 方案文档最核心的「规则与模型双轨」原则尚未落地 —— 因为规则引擎不存在。
  • 方案文档「合规校验工作台」「变更监控简报」两个应用层交付物未开工。
  • 一期验收标准「抽样问答引用准确率 ≥ 95%」未度量 —— 现有 eval 只有 retrieval 指标，没有「引用准确率」这个口径。

法规检索· 层级导航· 知识问答· 版本追溯· 合规审查· 风险预警· 审核预审

绿 已上线 · 黄 部分 · 红 未开工

推荐路径 先做快档的规则表 —— 它是「合规审查」整条业务线的唯一入口，且手工整理 50–100 条就能验证整条链路 （用户输入 → 判定 → 带原文引用）。这条链路跑通后，无论后面走哪档都不浪费。

更稳的做法：先盘点语料里有多少条限量表数据可自动抽取 —— 《饲料添加剂安全使用规范》实测已含「动物×mg/kg」结构化表格， 能自动抽就先自动抽再人工校，比纯手工整理快一个数量级。

8CTO 否决线

以下两项不会因为「快」而放行：

1无引用即输出 —— 合规结论没有条款原文支撑，一律拒答

当前 citation 校验已有雏形，要往严了做。这条直接对应方案文档「合规优先」原则，也是本系统唯一不可协商的底线。

2静默漏检 —— 规则表没覆盖到的物质，必须返回「规则未覆盖，需人工确认」

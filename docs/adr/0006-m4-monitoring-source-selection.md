## 背景

### 1. M4 的契约已在 ADR-004 里定义好,但从未验证可行性

ADR-004 把 ⑤ 法规监测(支撑域)定义为:

| 项 | 定义 |
|---|---|
| 通用语言 | 发布源(Source)、公告(Announcement)、版本差异(VersionDiff)、影响面(ImpactScope)、订阅(Subscription) |
| 聚合根 | `RegulationRelease`(一次法规发布) |
| 不变量 | 一个发布必须能算出「影响哪些物质/品类/标签声明」,**算不出则标记 `影响面未知`,不推送给用户** |
| 领域事件 | `RegulationReleaseDetected` → `RegulationVersionIngested` → `RulesRecalculated` |
| 表归属 | `regulation_releases` / `subscriptions` 归 ⑤ |

**但 ADR-004 只是纸面契约。** M4 排期估 4-6 周,主风险标注为「政府网站结构脆弱,站点改版即失效」。
本次开工前必须先回答:**数据源到底能不能爬?**

### 2. 业务动机:现有合规规则已经被改过,而项目完全不知道

这是本次调查挖到的**决定性事实**,它把 M4 从「可选增强」重新定义为「正确性保障」。

**D1 现状实测**(`compliance_rules`):

```
r_5853c87635aa  维生素D3  鱼类  min=500   max=2000  IU/kg
r_8e198a22824c  维生素D2  鱼类  min=3000  max=3000  IU/kg
```

**第1025号公告原文**(2026-05-29,实测从 `www.agri.cn` 抓到正文 2032 字):

> 五、修订《饲料添加剂安全使用规范》
> (一)在《饲料添加剂安全使用规范》维生素 D3「在配合饲料或全混合日粮中的最高限量
> (以维生素计)」的要求中,将「鱼类 3 000 IU/kg」修改为「**鲑科鱼 60 000 IU/kg**」、
> 「其他鱼 3 000 IU/kg」。

**第1028号公告**(2026-06-04):

> 二、第三部分饲料原料列表 增补「1.2.25 大米次米」等 **83 种**饲料原料和
> 「2.24 芥菜籽及其加工产品」等 7 个类别;删除「3.1.2 去皮扁豆」等 **10 种**无实际使用的
> 饲料原料;删除「4.12 食用瓜类及其加工产品」1 个类别;修订「1.1.1 大麦」等 **173 种**
> 饲料原料和「2.26 其它」等 4 个类别。

| 受影响对象 | 项目现状 | 2026 年内的实际变化 | 状态 |
|---|---|---|---|
| 维生素D3 · 鱼类限量 | 500~2000 IU/kg | 鲑科鱼 60000 / 其他鱼 3000 IU/kg | 🔴 **已过时** |
| `substance_catalog` 物质快照 | 387 条(2026 版汇编) | +83 原料 / -10 原料 / 173 处修订 | 🔴 **已过时** |
| 现有 D1 数据 | 静态快照 | 无任何机制发现变更 | 🔴 **盲区** |

**结论**:M4 不是「锦上添花的爬虫」。**没有 M4,合规速查(②)会静默地给出过时的限量判定**,
而这恰恰违背了项目最核心的「规则必须可溯源到现行条款」不变量。

## 决策

### 1. 数据源选型(实测后定)

实测了 3 个候选源,全部用真实 HTTP 请求验证,**不靠文档推测**:

| 源 | 可达性 | 列表页结构 | 正文提取 | 分页 | 结论 |
|---|---|---|---|---|---|
| `www.moa.gov.cn/govpublic/1/2/79/index.htm` | 200 | 司局索引,非公告列表 | — | — | ❌ 入口层级不对 |
| `www.moa.gov.cn/govpublic/` | 200 | 司局目录,无公告列表 | — | — | ❌ 不是列表源 |
| `www.moa.gov.cn/xmsyj/...` | 404 | — | — | — | ❌ 路径不存在 |
| **`www.agri.cn/zx/hxgg/`** | **200** | **规整** | **✅ 2032 字** | **index_1..19** | ✅ **主源** |
| `www.nahs.org.cn/xxcm/slzlaq/` | 200 | 专题页 | — | — | 🟡 辅源(人工整理的现行目录) |

**RSS / JSON / sitemap 全部 404** —— 政府网站没有机器可读接口,**只能解析 HTML**。
这是「爬虫脆弱」的根源,缓解办法见 §3。

**选 `www.agri.cn/zx/hxgg/` 作为主源。**

### 2. 为什么 agri.cn 比 moa.gov.cn 好

实测 `www.agri.cn/zx/hxgg/` 的链接结构:

```
中华人民共和国农业农村部公告 第1080号  →  ./202611/t20261109_8882458.htm
中华人民共和国农业农村部公告 第1075号  →  ./202611/t20261104_8881466.htm
关于印发《全国农药产业发展"十五五"规划》的通知 → ./202611/t20261103_8881176.htm
```

**三个结构性优势**:

1. **路径编码日期**(`202611/t20261109_8882458.htm`)—— 天然按时间排序,
   **不需要依赖列表页顺序**(列表页顺序变了不会漏数据)
2. **标题带公告号**(`第1080号`)—— 公告号是**权威唯一标识**,天然的主键
3. **正文可完整提取** —— 实测第1025号公告正文 2032 字,含全部修订细节

这三条让「变更检测不依赖精确 diff」成为可能:即使 HTML 结构变了,
**日期路径 + 公告号 + 标题**这三元组仍然可用。

### 3. 抗脆弱策略(应对「站点改版即失效」)

主风险已识别,但**有低成本的对冲**:

| 风险 | 对冲 |
|---|---|
| 列表页 HTML 结构变了 | **不解析列表页结构** —— 只提取 `href` 里符合 `t\d{8}_\d+\.htm` 的链接 + 其锚文本。结构变了只影响锚文本获取,日期路径仍在 |
| 正文容器 class 变了 | **多策略降级**:先按 `id/class` 匹配 `content\|TRS_Editor\|article`,失败则回退「取最长 `<p>` 连续块」,再失败则回退「全文去标签」 |
| 公告号提取不到 | 用**日期路径 + 完整 URL** 作为 fallback 主键 |
| 站点整体不可达 | **爬虫失败必须告警而非静默** —— 写入 `monitoring_runs` 表并产出 ERROR 级日志;连续失败达阈值置 `stale` 标记 |
| 一次只抓到列表页首页 | **必须翻页** —— `index_1.htm` .. `index_19.htm`(实测 200) |

### 4. 变更检测策略:文档指纹 + 公告号匹配,不做精确 diff

ADR-004 的不变量要求算出「影响哪些物质/品类/标签声明」,算不出则标 `影响面未知`。
精确 diff 需要存旧全文且要能对齐段落,成本高、易错。

**采用三级判定**:

```
① 公告号相同 + 指纹不同  → 公告被修订(同一号重新发布)
② 公告号新出现           → 新发布
③ 标题关键词命中受控词表  → 可能影响 ② 合规规则
```

第③级是**影响面推断**的入口。关键词表从项目已有资产反推:

| 关键词 | 推断影响 |
|---|---|
| `饲料添加剂安全使用规范` / `限量` / `最高限量` | ② 的 limit 规则需重算 |
| `饲料添加剂品种目录` / `饲料原料目录` | `substance_catalog` 需重算 |
| `禁` / `不得使用` / `禁止` | ② 的 prohibition 规则需新增 |
| `标签` / `GB 10648` | ③ 的 C3 标签审查受影响 |

**关键约束(写进领域层)**:
- **不自动改数据** —— 只产出「变更影响报告」+ `RegulationReleaseDetected` 事件,
  由人工校核决定是否更新规则。理由:② 的不变量是「规则未审核不参与判定」,
  自动改规则会绕过这个闸门。
- **影响面算不出必须显式标 `影响面未知`,不推送** —— 沿用 ADR-004 原文。

### 5. 分层落点(遵守 ADR-004 的 R1-R5)

```
domain/monitoring/
  regulation-release.aggregate.ts    RegulationRelease 聚合根
  release-detector.service.ts        ★ 纯函数:指纹/公告号/影响面判定(零 I/O)
  impact-scope.vo.ts                 ImpactScope 值对象
application/monitoring/
  collect-releases.usecase.ts        编排:抓取 → 判重 → 落库 → 发事件
interfaces/acl/
  moa-source.acl.ts                  ★ 政府网站防腐层(所有 fetch 在这)
infrastructure/persistence/d1/
  monitoring.repository.impl.ts       D1 实现
```

**R3 强制**:所有 `fetch()` 只允许出现在 `interfaces/acl/moa-source.acl.ts`。
架构测试会扫 `domain/` 与 `application/`,发现 `fetch(` 即失败。

## 取舍

| 方案 | 优点 | 缺点 | 选择 |
|---|---|---|---|
| **仅列表页监控 + 人工复核** | 1-2 天,极简 | 只有标题,**看不到正文里的限量修订**(如 D3 鲑科鱼 60000)——恰恰漏掉最关键的信息 | 否 |
| **抓正文 + 关键词影响面推断**(本 ADR) | 能抓到「限量改了」这种真变更;不自动改数据,安全 | 关键词表需人工维护;正文解析有降级链 | **是** |
| **全文精确 diff + 自动改规则** | 最自动 | 会绕过 ② 的校核闸门;对齐段落易错;**违反项目核心不变量** | 否 |
| **等 RSS/JSON 接口** | 最稳 | **实测全部 404**,政府网站没有 | 否(已排除) |
| **人工定期看公告** | 零技术成本 | 就是当前状态 —— 已经漏了 D3 鲑科鱼 60 000 的修订 | 否 |

## 还债触发器

| 触发条件 | 动作 |
|---|---|
| 站点 HTML 结构变化导致抓取数为 0 | 修 `moa-source.acl.ts` 解析器 + **补一条带真实 HTML 样本的解析单测** |
| 关键词表命中率 < 50%(抽查 20 条公告) | 扩关键词表 |
| 影响面误报率 > 30% | 改用「公告号 + 制度名」精确匹配,放弃关键词猜测 |
| 累计漏报已知变更 > 1 次 | 评估换源(`nahs.org.cn` 现行目录做交叉验证) |

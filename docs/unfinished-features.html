#5 组合/条件规则抽取

#原文形态示例难点

关联策略(确定性,不重跑 GraphRAG):权威出处 + 三路变体。 ① source_article_id —— 每条物质在《品种目录》的出处条文(零猜测, 不变量 2 的溯源字段)② 括号别名 核黄素(维生素B2) → 维生素B2 ③ name_en ④ substance_alias。 实测 387 条全部有 source_article_id,且都指向《品种目录》的 4 个条文 —— 零猜测。

为什么不用 GraphRAG 重跑:build/graphrag/output/*/artifacts/*.parquet 已清理;run.sh 要 LLM key 逐章节跑,那次只跑了 16 个 chunk,而语料早扩到 3145 条文, 产物与现状严重脱节。

关键决策 —— 别名一对多 → 一律不收录 维生素B1 → 盐酸硫胺/硝酸硫胺;螯合物 → 9 个络合物。 查到了也只能随便挑一个,那是在猜。这与 ② 合规规则的 alignSubstanceName 是同一条纪律:候选不唯一就不采用。宁可「查不到」,也不给错答案。
结果:124 个候选别名 → 收录 117 条,剔掉 7 条一对多的。

顺带修掉的 3 个真 bug:

  • 顶栏「实体」跳 /entity/农业农村部 —— 该实体生产实测命中 0 条, 点进去直接 404。481 个实体只能手动拼 URL 到达。改跳新增的实体列表页。
  • 实体列表中文搜索用 LIKE 无效 —— SQLite 的 LIKE 只对 ASCII 有效,测中文永远 false。实测生产 ?q=维生素 → 0 条,而 ?q=L-赖氨酸 → 1 条(能中是因为前半段 "L-" 是 ASCII)。改用 instr()(二进制子串查找),实测 维生素 0 → 15 条。 换回 LIKE 不会报错,只是永远搜不到东西。
  • description 为 null 时返回 undefined —— 与 number 同源的契约缺口,前端拿到 undefined 会显示 "undefined"。归一化成空串。

新增入口:GET /api/entities(分页 + 类型过滤 + 名称搜索,limit 封顶 200) + 前端 /entities 实体列表页。

5明确不做(数据源不存在,不是没排期)

项原因
企业资质审查语料里「生产许可证」命中 88 个文件,但那是许可证的条款(规定怎么办理),不是企业的实际证件数据。语料是法规,不是证件库。
抽检结果「同类产品风险提示」国家饲料质量抽检结果由农业农村部以公告(PDF)形式发布,无 API;粒度是「产品批次 + 检验结论」,没有企业配方数据 —— 无法做「同类产品」关联。可降级为「抽检公告聚合检索」,语义不同,需在产品文档写清。
合规日历 · 换证/年检提醒需企业侧证件到期日,语料里没有。
真正的历史版本回溯农业农村部不提供结构化历史版本,只能积累上线后的变更。
跨模块 Planner(复杂问题拆解)法规问答大多是单跳检索。真正的复杂场景(配方审查)走确定性接口,不该走 LLM Planner。低频高价值,等真实提问日志出来再定。
「物质 → 可用替代品」映射这是新产品审定的知识,语料是法规不是审定结论库。v1 只给「允许区间」,替代建议不承诺。
